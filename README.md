# DAS Kai

DAWの音を、仮想オーディオデバイスなしでOBSに送るプラグインです。DawAudioStreamer(yoruhinot 作)を改造し、次の3つを足しています。

- **クロックずれの吸収**: DAWのオーディオインターフェースとMac本体は別々のクロックで動いています。そのずれを再生速度のごくわずかな伸び縮み(数十ppm、音程にして0.1セント未満)で吸収し、長時間の配信でも歌とOBSの他の音の合い方が変わらないようにします。
- **時刻の受け渡しと遅延の自動補正**: 音がDAWで処理された時刻をOBSに渡します。OBSはその時刻に合わせて音を置きます。プラグインからOBSまでの受け渡しの遅れは自動で差し引かれます。配信と録画では、映像も同じ時刻を基準に並べられます(OBSのソースコードで確認。実機の録画での確認はまだです)。
- **手動補正**: 歌い手がオケを聞く経路の遅れなど、プラグインから測れない分を手で足せます。

対応環境は macOS 13 以降の Apple Silicon、OBS 32 系です。Windows には対応していません。

## 入れ方

ビルドしてから、付属のスクリプトで入れます。入る場所はこのユーザーの3か所だけです。

```bash
scripts/install.sh
```

- `~/Library/Audio/Plug-Ins/VST3/DAS Kai.vst3`
- `~/Library/Audio/Plug-Ins/Components/DAS Kai.component`
- `~/Library/Application Support/obs-studio/plugins/das-kai-obs.plugin`

元の DawAudioStreamer とは名前も中身の識別子も別なので、両方入れたままで構いません。

## 使い方

1. DAW を開き直し、マスターの最後に「DAS Kai」を1個挿します(VST3 か AU)。
2. OBS を開き直し、「ソース」の[＋]から「DAS Kai（DAW）」を追加します。設定は不要です。
3. DAW を再生し、プラグイン画面の OBS 欄が「受信中」になることを確かめます。

## プラグイン画面の見方

画面は日本語で開きます。右上の小さな「日本語 ・ EN」で英語表示に切り替えられ、選んだ言語は DAW のプロジェクトに保存されます。

| 表示 | 意味 |
|---|---|
| OBS 欄の「受信中」/「待機中」 | OBS が受け取っていれば「受信中」。「待機中」は OBS 側のソースがまだない状態 |
| クロックのずれ -15 ppm | オーディオインターフェースのクロックが Mac 本体のクロックより何 ppm(100万分のいくつ)速いか。数字の色は、緑が ±100 ppm 以内(ふつうの範囲)、黄が 100〜300 ppm、赤が 300 ppm 超(ふつうの機材ではまず出ない値。推定がこれだけ外れていると、OBS 側の細かな補正(±300 ppm まで)では埋めきれず、音が途切れやすい)。ふつうは ±100 ppm 以内で、数十 ppm がよくある値です(-15 ppm なら 1 分で約 0.9 ミリ秒遅れる)。値は数秒〜数十秒かけて落ち着き、その後はほとんど動きません。DAS Kai はこのずれを吸収するので、0 である必要はありません。起動直後や DAW が処理を止めて再開した後は「クロックを合わせています…」と出ます。黄や赤が出た時の見分け方と対処は、下の「クロックのずれが大きい時」にあります |
| 「タイミング補正」の大きな数字 | OBS の中で、DAW の音を何ミリ秒早めているか(自動 + 手動)。自動の分は、DAW から OBS へ音を受け渡すための待ち時間です。DAW が一度に処理する長さ(バッファ)と余裕の分で決まるので、プロジェクトの中身(トラック数やプラグイン)では変わらず、空のプロジェクトでも同じ値になります。例: 48 kHz・バッファ 1024 なら 40 ミリ秒。音が遅れて届いた時だけ、遅れた分だけ増えます(OBS の音が一度途切れます)。マイナスの補正が勝つと「遅らせています」と出ます。変えた直後は「反映中…」と出て、OBS に反映されると数字が変わります。合計は 850 ミリ秒が上限です |
| 自動補正 | 受け渡しの遅れを自動で差し引くかどうか。通常はオン |
| 手動補正 | 手で足す補正(-100〜+100 ミリ秒、0.1 ミリ秒刻み)。プラスで DAW の音を早めます。Shift を押しながら動かすと細かく動き、数字の欄をクリックすると値を直接入力できます。ダブルクリックで 0 に戻ります |

## 手動補正の値の決め方

歌い手がオケを聞く経路の遅れ(ブラウザ → スピーカーやヘッドホン)は、機材と聞き方が同じなら毎回同じです。一度測れば使い回せます。

1. OBS の録画を「トラックを分けて保存」にし、オケ(ブラウザ)と DAS Kai を別トラックにします。
2. オケの拍に合わせて、マイクの前で手を数回たたいて録画します。
3. 録画を DAW や編集ソフトに読み込み、オケの拍と手拍子の波形のずれをミリ秒で測ります。
4. 手拍子が遅れていれば、その値を「手動補正」に入れます。

## クロックのずれが大きい時

数字が大きいことそのものは問題ではありません。DAS Kai は、DAW が知らせるクロックの速さにそのまま合わせて OBS へ渡します。上限は ±1500 ppm で、1000 ppm のずれは試験で途切れなしを確認しています。問題になるのは、DAS Kai がクロックの速さを読み違えている時です。読み違えた分は OBS 側が細かく補正しますが、その補正は ±300 ppm までなので、それを超えて外れると音が途切れます。

画面の数字だけでは、本当にずれているのか読み違えているのかは分かりません。数字の動き方と OBS の音で見分けます。

1. 灰色の「クロックを合わせています…」の間は、色が付くまで待ちます。起動直後は数秒〜数十秒かかります。
2. 数字が一つの値で落ち着いていて、OBS の音も途切れない時は、クロックが本当にずれています。そのまま使えます。気になる時は、オーディオインターフェースのクロックの設定を確かめます。外部のクロック(ワードクロック・S/PDIF・ADAT など)に合わせる設定になっていて、その必要がなければ「内部(Internal)」に戻します。
3. 数字が大きく上下する、OBS の音が途切れる、OBS のログ(「知っておくこと」を参照)に段差や待ち時間を延ばした記録が続く、のどれかがある時は、DAS Kai が読み違えています。DAW が先読みでまとめて処理する時に起きやすくなります。
   - その場の手当て: DAS Kai を一度無効にして、有効に戻します(バイパスではなく無効化です。バイパスでは合わせ直しません)。クロックを最初から合わせ直します。OBS の音が一瞬切れるので、配信の前に行います。
   - 先読みを弱める: Cubase は「スタジオ」→「スタジオ設定」→「オーディオシステム」で ASIO-Guard を切るか、段階を下げます。Studio One は「オーディオ設定」の「処理」で「ドロップアウト保護」を下げます。どちらも DAW の負荷が上がり、DAW 側で音が途切れやすくなることがあるので、様子を見ながら変えます。
   - 開発者へ知らせる: その時の OBS のログを残してください。開発用の記録の道具を使うと、その時の DAW の処理の仕方をそのまま録って、今の版で再生して確かめられます(記録の間は OBS を閉じます)。

## 知っておくこと

- OBS の受け取り側は、OBS のログ(OBS のメニューの「ヘルプ」→「ログファイル」)に `[DAS Kai]` で始まる行を書きます。受信の開始と停止、DAW の処理のタイミングの段差、音の遅れで待ち時間を延ばしたこと、DAW のクロックのずれと途切れの回数(1分ごと)が残るので、音が途切れた時や表示がおかしい時は、このログで何が起きたかを確かめられます
- 手動補正や自動補正を変えると、OBS の音が一瞬途切れます。ふつうは 0.1 秒前後で、OBS に新しい時刻を受け入れさせるための切れ目です。手動補正を大きく減らした時は、減らした分だけ長く途切れます(-100 ミリ秒なら約 0.1 秒長く)。配信中ではなく、準備の時に合わせてください。
- OBS は、遅れて届く音に合わせて全体の待ち時間を自動で増やします。一度増えた待ち時間は、OBS を開き直すまで減りません。配信と録画の音と映像は揃ったままです。
- OBS の画面のプレビューとモニター音は、この待ち時間の分だけずれて見えることがあります。配信と録画には影響しません。
- DAW の書き出し(バウンス)中は送りません。バイパス中は無音を送ります。
- 旧仮称「Kinu Stream」で OBS に追加したソースは、そのまま DAS Kai のソースとして動きます。ソースの名前だけは古いままなので、必要なら OBS で名前を変えてください。
- 送れるのは、同じユーザーで同時に 1 個だけです。2 個目は画面に「1個のみ」と出ます。
- Cubase の ASIO-Guard など、DAW が先読みで処理する設定では、処理のタイミングが段差状に前後します。DAS Kai はこの段差をクロックのずれと区別して扱います(先読みを真似た実時間の試験と、39 種類の呼び出し方の模擬で確認。実際の Cubase での新しい版の確認はまだです)。先読みの分だけ自動補正が多めにかかる可能性があり、その場合は手動補正をマイナスにして合わせます。
